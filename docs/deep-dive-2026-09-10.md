## Root causes and fixes shipped (commit 6c03409, plus 5f0a437 from the parallel session)

### 1. The crash: stale service-worker cache
next-pwa's default `others` runtime rule cached HTML documents and RSC payloads for 24 hours with NetworkFirst and a 10-second timeout. Runtime caches survive service-worker updates, and the repo deploys 10–30 times a day, so the cache always held pages from several deployments. Any slow or failed fetch was answered with a page from an old deployment, hydrated against the current bundle. That is the null router tree.

Fixed in `next.config.js`: navigations and RSC requests are NetworkOnly, the `others` rule is removed, `reloadOnOnline` and `cacheStartUrl` are off. `public/push-worker.js` deletes the poisoned cache on activate so existing phones self-clean. `AutoCheckIn` no longer calls `router.push` and `router.refresh` in the same tick. The parallel session added automatic reload from the error boundaries (5f0a437).

### 2. Random logouts and "Check-in failed" after login: middleware
- Redirects were new responses, so auth cookies Supabase had just rotated were dropped. The browser then presented a revoked refresh token: "Already Used".
- Unauthenticated `/api/*` calls got a 307 to the login HTML page; the client's `res.json()` threw.
- A GoTrue network blip was treated as "logged out".
- Sign-out was global, killing the student's session in the native app, Safari, and the other domain at once: "Refresh Token Not Found".
- Service-worker scripts and crash telemetry went through the session check.

Fixed in `middleware.ts`, `lib/middleware/authGate.ts` (tested), `app/(auth)/login/actions.ts`.

### 3. GPS flags and false rejections
- The QR sticker encodes `tranmeretracker.vercel.app`. Location permission and login cookies are per-origin, and the prompt fired on page load with no explanation from a domain students don't recognise. iOS Safari remembers "Don't Allow" per site and replays it instantly forever. That is the 25 students. The commit that blamed a third-party in-app browser was wrong: the `utm_source` is baked into the QR image and appears on every scan.
- Since the Wi-Fi fallback shipped on 09-08, coarse fixes report the Wi-Fi provider's address. Seven students were rejected at exactly 3319 m and two at exactly 1622 m, identical coordinates each time. The server ignored accuracy entirely.
- The RPC compared windows with seconds while the app used minutes, so a tap at 10:29:50 could be refused after the 16-second GPS wait.

Fixed: migration 066 (applied to production) makes the fence accuracy-aware and compares at minute precision; `geoUtils.isInsideFence` and tap-checkin mirror it. Students who have blocked location now see how to fix it on the success screen. Staff no longer get a push for a permission-denied flag (the flag stays in the day view).

### 4. Native app users never got most staff alerts
`sendPushNotificationToUser` only read `push_subscriptions`. Missed-check-in sweeps, safeguarding nudges and cases, GPS rejections, flagged check-ins, AM/PM digests, and parent notices all route through it. Now dual-channel (web push + FCM), with tests.

### 5. Deploy blocked
`What's` → `What&apos;s` in the wellbeing page (5f0a437). Production is now on that commit.

## Still open — needs your decision

1. **Move the stickers to app.thesolarcampus.com.** Re-encode the QR/NFC tags, add `applinks:app.thesolarcampus.com` to `ios/App/App/App.entitlements` and the AASA, add the host to `AndroidManifest.xml`, ship a native build, then enable the redirect in `next.config.js`. Until then every phone has two logins and two location grants.
2. **Native rebuild needed** for the above plus: `NSCameraUsageDescription` missing from `Info.plist` and `CAMERA` missing from the Android manifest (nutrition barcode scanner will crash the iOS app / be denied on Android).
3. **PIN reset logs the student out everywhere** (`app/api/admin/reset-pin`, `ChangePinForm`). GoTrue behaviour; either accept it and tell the user, or leave as is.
4. **Lunch/PM check-in rates are very low.** Not a bug I can see in code; likely awareness or the sticker location. Worth watching next week now flags are quieter.
5. **Cron schedules** for the AM/PM digests are single UTC entries and will drift an hour when clocks go back on 25 Oct 2026. `lunch-ending` shows the dual-entry pattern to copy.
6. **Cron insert noise**: safeguarding-check, missed-checkin-sweep and nudge-log inserts rely on unique constraints and generate ~250 Postgres errors a day. Harmless, but it buries real errors. Switch to `upsert(..., { ignoreDuplicates: true })` or check-before-insert.
7. **Push opt-in on iOS** only works from a Home Screen install; the button should say so instead of failing with "Load failed". Android SW install can exceed 45 s on cold Wi-Fi; wait instead of timing out.
8. **Supabase advisors**: 74 RLS policies re-evaluate `auth.uid()` per row, 154 overlapping permissive policies, 16 SECURITY DEFINER functions executable by `anon`. Not user-visible at 51 students; fix when convenient.
9. **Local dev**: `npx tsc --noEmit` reports "Cannot find name 'it'/'expect'" in every test file. `@types/jest` is not a declared dependency (not in package.json or the lockfile), so this is a pre-existing gap in the local type-check rather than a code error; Jest itself and the Vercel build both pass. Adding `@types/jest` as a devDependency would make the local check clean.

## Review follow-up (second pass, same day)

An independent review of `6c03409` found two real defects in the fix itself, corrected in the follow-up commit:

- **Open redirect.** Honouring `?next=` for an already-signed-in user on `/login` used string checks; the URL parser strips tab and newline first, so `/login?next=/<tab>/evil.example` would have sent a signed-in user off-site. `safeNextPath` now rejects control characters and resolves the value against a dummy origin, keeping it only if the origin is unchanged.
- **The push+refresh pair survived on the main success path** of `AutoCheckIn` (only the already-checked-in branch had been changed), which also meant the location-denied notice auto-navigated away after 2.5 s. Fixed; the component test now uses fake timers so it would fail if this regressed.

Three hardenings from the same review: `dynamicStartUrl: false` (next-pwa was still caching a blank `/` response; the worker also purges that cache), `geo_permission_denied` is only honoured when no coordinates were sent (so an off-site tap cannot relabel its own flag or mute the staff push), and a coarse Wi-Fi fix on the in-app tap path is allowed but flagged "coarse fix" rather than passing silently.

Live checks against production after deploy (unauthenticated): API calls get a JSON 401, `sw.js` and `push-worker.js` are served without a login redirect, crash telemetry POSTs succeed, page redirects preserve the QR tag, and the deployed worker contains the navigation/RSC network-only rule.
